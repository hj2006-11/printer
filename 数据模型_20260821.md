# CCPC 本地打印服务 数据模型（D3）

> 状态：已冻结（与《接口书面约定 v1.0》一致）。本模型仅覆盖主路径上的关键数据对象，不做与主路径无关的完整库设计。

## 1. 核心实体：Task（打印任务）

内存中的任务对象，同时是 JSON 序列化的传输载体。

```
Task
├── task_id      string    任务ID：T{4位序号}-{unix秒}，如 T0001-1755718800
├── type         string    "ticket" | "code"
├── status       string    "pending" | "completed" | "failed"
├── message      string    失败原因（成功时为空，omitempty）
├── output_path  string    PDF 产物路径（仅 completed/failed 且有产物时，omitempty）
├── created_at   time.Time 创建时间（RFC3339）
└── data         object    按 type 分组的具体载荷
    ├── [ticket] team       string  队名
    │           problem    string  题号
    │           pass_time  string  通过时间（YYYY-MM-DD HH:MM:SS，可空）
    └── [code]   lang       string  语言标识（cpp/c/java/python/...，可空）
                source     string  源代码全文
```

### 状态机

```
                +-----------+
  提交任务      |  pending  | 排队中（已入队未处理）
               +-----------+
                    |
        +-----------+-----------+
        |                       |
   渲染+打印成功           渲染失败 / 打印硬失败
        |                       |
        v                       v
+-------------+          +-----------+
|  completed  |          |  failed   | message 记录失败原因
+-------------+          +-----------+
```

转换规则：

- `pending → completed`：渲染 PDF 成功，且打印成功或 PDF 兜底生效。
- `pending → failed`：渲染失败，或打印硬失败（如 Chrome 不存在、超时）。
- 状态不可回退，无取消操作（MVP 范围外）。

## 2. 队列与存储：Queue

```
Queue
├── ch      chan *Task   有缓冲任务队列（容量 10），worker 消费
├── tasks   map[string]*Task   task_id → Task 索引（内存存储）
├── mu      sync.RWMutex      并发保护
├── rdr     *render.Engine    渲染引擎（依赖注入）
├── prn     *printer.Adapter  打印适配器（依赖注入）
├── outDir  string            PDF 输出目录
└── counter int               任务序号计数器（生成 task_id）
```

说明：

- 单 worker（`go q.worker()` 消费 `ch`），保证打印串行，避免打印机争用。
- `Submit`：加锁递增 counter、生成 ID、置 pending、写 map、入 channel。
- `Get`：读锁查询 map，返回 `(Task, bool)`。
- **不做持久化**：服务重启即清空（D1 已列为"不做"项）。

## 3. 产物与配置对象

| 对象 | 路径 | 内容 | 用途 |
| --- | --- | --- | --- |
| PDF 产物 | `{workdir}/output/{type}_{纳秒}.pdf` | 渲染结果 | 打印输入 / 无打印机时的最终产物 |
| 临时 HTML | `{workdir}/output/{type}_{纳秒}.html` | 渲染中间态 | Chrome 输入，渲染后删除 |
| `port.txt` | `{workdir}/port.txt` | `127.0.0.1:{port}\n` | 记录实际监听端口，供页面/人工读取 |

## 4. HTTP 请求/响应数据模型

### 请求：POST /api/v1/tasks

```
SubmitRequest
├── type  string  必填，取值 ticket|code
└── data  object  按 type 分组
    ├── ticket: { team: string 必填, problem: string 必填, pass_time?: string }
    └── code:   { source: string 必填, lang?: string }
```

### 响应：POST /api/v1/tasks（202）

```
SubmitResponse
├── task_id     string
├── status      string  固定 "pending"
└── created_at  string  RFC3339
```

### 响应：GET /api/v1/tasks/{id}（200）

```
TaskView = Task（见 1）序列化：
├── task_id, type, status
├── message?, output_path?
├── created_at
└── data  （原样回传 type 分组数据）
```

### 错误响应（统一）

```
ErrorEnvelope
├── error
    ├── code     string  INVALID_ARGUMENT | NOT_FOUND | METHOD_NOT_ALLOWED
    └── message  string  可读信息
```

## 5. 数据流（主路径）

```
用户填表
  │  JSON SubmitRequest
  ▼
POST /api/v1/tasks ──校验──> 构造 Task(status=pending)
  │                                  │ Submit
  ▼                                  ▼
202 SubmitResponse  ←────────  Queue.Submit（入 map + 入 ch）
                                      │ worker 消费
                                      ▼
                              RenderEngine.RenderTicket/RenderCode
                                      │ HTML→PDF
                                      ▼
                              PrinterAdapter.Print(pdf)  [无打印机→PDF兜底]
                                      │
                                      ▼
                              Queue.update(status=completed|failed, output_path, message)
                                      │
页面轮询 GET /api/v1/tasks/{id}  ◄────┘
```

## 6. 与接口约定的一致性核对

| 数据模型 | 接口约定 | 一致 |
| --- | --- | --- |
| `data` 按 type 分组 | 请求体 `{type, data:{...}}` | ✅ |
| 状态枚举 pending/completed/failed | 状态机与状态字段 | ✅ |
| 错误结构 error.code/message | 统一错误格式 | ✅ |
| created_at RFC3339 / pass_time 可读时间 | 时间格式约定 | ✅ |
| task_id 格式 | 任务 ID 约定 | ✅ |
